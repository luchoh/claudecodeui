## Findings & Remediation (ordered by severity)

### HIGH: Command injection risk in git endpoints (shell interpolation)
**Where**
- `server/routes/git.js` uses `execAsync` with interpolated user input in multiple commands.

**Evidence**
- Command: `rg -n "execAsync" server/routes/git.js > /tmp/claudecodeui-security-audit/server-routes-git-execAsync.txt`
- Output: `/tmp/claudecodeui-security-audit/server-routes-git-execAsync.txt` shows interpolated usages like:
  - `git status --porcelain "${file}"` (line 171 in that file)
  - `git show HEAD:"${file}"` (line 192)
  - `git diff -- "${file}"` (line 199)
  - `git diff --cached -- "${file}"` (line 206)
- Example excerpt with line numbers:
  - Command: `nl -ba server/routes/git.js | sed -n '150,230p' > /tmp/claudecodeui-security-audit/server-routes-git-diff-nl.txt`
  - Output: `/tmp/claudecodeui-security-audit/server-routes-git-diff-nl.txt` shows the interpolated `file` in commands.

**Why it matters**
- `exec` executes via a shell; interpolated inputs can be used to inject shell metacharacters. This risks RCE.

**Remediation**
- Replace `execAsync` with `spawn`/`execFile` and pass args as arrays (no shell).
- Add strict validation/normalization for `file`, `branch`, `remote`, `commit`, `message` inputs (e.g., allowlist regex + repo-root resolution).
- Add unit tests with payloads like `$(...)`, backticks, `;`, `&&` to confirm rejection.

### HIGH: Command injection risk in git config endpoint
**Where**
- `server/routes/user.js` applies git config via `execAsync` using interpolated `gitName`/`gitEmail`.

**Evidence**
- Command: `nl -ba server/routes/user.js | sed -n '40,90p' > /tmp/claudecodeui-security-audit/server-routes-user-exec-nl.txt`
- Output: `/tmp/claudecodeui-security-audit/server-routes-user-exec-nl.txt` shows:
  - `execAsync("git config --global user.name \"${gitName.replace(/\"/g, '\\\\\"')}\"")`
  - `execAsync("git config --global user.email \"${gitEmail.replace(/\"/g, '\\\\\"')}\"")`

**Why it matters**
- Only double-quotes are escaped; other shell metacharacters are not. This allows injection in `gitName`.

**Remediation**
- Use `spawn('git', ['config','--global','user.name', gitName])` and same for email.
- Enforce max length and reject control characters in `gitName`.

### HIGH: XSS via PRD preview (unsafe HTML rendering)
**Where**
- `src/components/PRDEditor.jsx` renders markdown with `dangerouslySetInnerHTML` and a regex-based renderer that does not escape HTML.

**Evidence**
- Command: `nl -ba src/components/PRDEditor.jsx | sed -n '480,720p' > /tmp/claudecodeui-security-audit/src-components-PRDEditor-nl.txt`
- Output: `/tmp/claudecodeui-security-audit/src-components-PRDEditor-nl.txt` shows `renderMarkdown()` and `dangerouslySetInnerHTML` usage.

**Remediation**
- Replace `renderMarkdown` with a library + sanitizer (e.g., `marked`/`markdown-it` + `DOMPurify`), or render markdown to React elements.
- Add tests with HTML payloads (e.g., `<img onerror=...>`) to confirm sanitization.
**Severity note**
- Elevated to HIGH per stakeholder consensus; verification required for token storage/exposure paths in the UI context.

### HIGH: Token leakage risk in clone workflows
**Where**
- Token is embedded in GitHub URL in `server/routes/agent.js` and `server/routes/projects.js`; stderr logging may expose tokens.

**Evidence**
- Command: `nl -ba server/routes/agent.js | sed -n '330,410p' > /tmp/claudecodeui-security-audit/server-routes-agent-clone-nl.txt`
- Output: `/tmp/claudecodeui-security-audit/server-routes-agent-clone-nl.txt` shows token in URL and stderr logging.
- Command: `nl -ba server/routes/projects.js | sed -n '520,600p' > /tmp/claudecodeui-security-audit/server-routes-projects-clone-nl.txt`
- Output: `/tmp/claudecodeui-security-audit/server-routes-projects-clone-nl.txt` shows token-in-URL clone path.

**Remediation**
- Avoid token-in-URL cloning; use `GIT_ASKPASS`, `GIT_TERMINAL_PROMPT=0` with credential helper, or `http.extraHeader` to pass auth.
- Redact tokens from all logging (stderr/stdout/URL logs).
**Severity note**
- Elevated to HIGH per stakeholder consensus; still contingent on whether tokenized URLs are used in the active deployment.
